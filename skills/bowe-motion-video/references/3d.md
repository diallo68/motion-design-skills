# 3D: isometric and perspective scenes

`engine/scene3d.js` adds a Three.js stage to a video page. It runs on the same clock as everything else
(`window.seek(t)` renders the frame), so 3D frames are exact and identical every render. Titles, chips and the end
card stay in HTML above the canvas, and `check.mjs`, sound and voice work as usual.

Use 3D when the brief asks for it, or when the product is best shown as objects in a small world: a delivery
route, an app among the things it helps with, a machine that shows a process step by step. Otherwise the 2D moves
are faster to make and to render.

## What the reference films do (measured)

Six isometric showreels and app spots were studied frame by frame (Dribbble shots chosen by the person, kept
locally, never copied). What they share:

- **One continuous shot**, 4–12 s, no cuts. The camera barely moves (a slow turn of a few degrees, or none); the
  objects carry the motion: they come out of the ground, slide on the grid, travel a conveyor, pop beside a phone.
- **Matte, clay-like objects with rounded edges**, soft studio light, soft contact shadows, no hard specular.
- **A narrow palette**: one or two light neutrals plus one accent (blue, green, gold on graphite), and a ground in
  the same family as the background.
- **A centred cluster** filling 50–60 % of the frame, with air around it; the cluster reads as one object.
- **UI inside the world**: a phone or a card in the scene carries the product's real screen; the screen changes
  on the beat instead of the camera cutting.
- Loops that work as a whole: the last frame could flow into the first.

What a browser can do: clean, readable, well lit scenes at this level. What it cannot: the path-traced light,
glass and reflections of a Cinema 4D or Blender render. Promise the first, not the second.

## A scene

```html
<script type="importmap">{ "imports": { "three": "./node_modules/three/build/three.module.js",
                                        "three/addons/": "./node_modules/three/examples/jsm/" } }</script>
<script src="engine/motion.js"></script>
<script type="module">
  import { stage } from './engine/scene3d.js';
  const frame = { story: { top: .33, bottom: .9 }, landscape: { top: .08, bottom: .95, left: .48, right: .97 } }[FORMAT]
             || { top: .28, bottom: .96 };
  const s = await stage({ camera: 'iso', light: 'soft', frame });
  const ground = s.place(s.slab(10, 10));          s.rise(ground, 0.1, { depth: 4 });
  const phone = s.place(s.phone({ screen: 'assets/screens/home.png' }), 0.4, 0, -0.6, Math.PI / 4);
  s.rise(phone, 3, { depth: 9 });
  s.screens(phone, [{ at: 0, src: 'assets/screens/home.png' }, { at: 6.3, src: 'assets/screens/quiz.png' }]);
  s.orbit(0, 12, 8);                                // the whole shot turns 8°
  s.done();                                         // fit, record the rest pose, render on seek
</script>
```

`init.mjs` adds `three` to the project; `npm install` brings it. The template `iso-promo` is a working example in
all four formats.

## Stage options

| Option | Values | Meaning |
|---|---|---|
| `camera` | `iso` (orthographic, true isometric), `perspective` | `direction: [x, y, z]` changes the angle, `fov` the lens |
| `light` | `soft` (cream studio), `cool` (blue-white), `night` (dark ground, warm key) | measured on the references |
| `frame` | `{ top, bottom, left, right }` fractions of the canvas | where the scene sits: under the title, or beside it in landscape |
| `shadows` | `true` | soft contact shadows |

The background is the page's CSS (a gradient in the style's colours); the canvas is transparent.

## Objects

`slab(w, d)` the ground (top at y = 0) · `tiles(n, size)` raised tiles · `block(w, h, d, color)` · `phone({ screen })`
· `laptop({ screen })` · `card({ accent | image })` a floating UI card · `coin({ symbol: 'check'|'plus'|'star' })` ·
`books(colors)` · `pencil()` · `cap()` · `pin()` · `svg(markup, { size, depth })` a logo or icon extruded ·
`image(src, w)` · `uiTexture({ title, rows })` a stand-in screen for drafts. Place with `s.place(obj, x, y, z, rotY)`.

A screen is a real capture whenever the app runs (`scripts/capture-app.mjs`); `uiTexture` is only for templates
and drafts.

## Moves

| Move | Use |
|---|---|
| `rise(obj, at, { depth })` | comes up out of the ground (the slab hides what is below) |
| `pop(obj, at)` | grows from nothing with a small overshoot: cards, coins, badges |
| `drop(obj, at, { height })` | falls and lands with a bounce: books, boxes |
| `slide(obj, at, { from: [dx, dy, dz] })` | slides in along the grid |
| `sink`, `vanish` | leaves (exits are about half the entrance) |
| `spin`, `turn` | turns on an axis |
| `along(obj, points, at, { dur })` | follows a path: a conveyor, a scooter on a route |
| `hover(obj, from, to)` | a gentle bob; one or two objects at most |
| `screens(device, [{ at, src }])` | the phone's screen changes on the beat |
| `show(obj, from, to)` | present only between two times |
| `orbit(at, dur, degrees)`, `zoom(at, dur, factor)` | the camera turns around the scene or punches in |

An object is invisible before its entrance move starts. Stagger entrances 0.2–0.4 s apart, biggest first (ground,
then the hero device, then props, then floating cards); the camera turns 5–10° over the whole shot at most.

## Rendering

WebGL renders through SwiftShader in headless Chromium, so it works without a GPU. Expect about 0.4–0.8 s a frame
at 1080×1920 with shadows: check one format first, render the others after. `check.mjs` reads the HTML text only;
look at the contact sheet for the 3D.
